The `navigation` object in `docs.json` defines the complete structure of your docs site — which pages appear in the sidebar, how they are grouped, and whether they are organized under multiple top-level tabs. Getting navigation right makes the difference between docs readers can explore confidently and docs they quietly abandon.

<Warning>
  The `navigation` field must always be a **JSON object**, never an array. A common mistake is setting it to an array of groups directly. Mintlify will not render your sidebar correctly if `navigation` is not an object with either a `tabs` or `groups` key.
</Warning>

## Single-section sites

If your docs cover one product area without distinct top-level sections, use a `groups` array directly inside the `navigation` object. This renders a single sidebar with all your groups listed vertically.

```json docs.json
"navigation": {
  "groups": [
    {
      "group": "Get Started",
      "pages": ["introduction", "quickstart"]
    },
    {
      "group": "Guides",
      "pages": ["guides/authentication", "guides/webhooks", "guides/pagination"]
    }
  ]
}
```

Each string in `pages` corresponds to the file path of an MDX file in your repository, **without the `.mdx` extension**. A file at `guides/authentication.mdx` is referenced as `"guides/authentication"`.

## Multi-tab sites

For larger doc sets — for example, a product with separate user guides and an API reference — use a `tabs` array. Each tab appears as a clickable item in the top navigation and has its own independent set of groups.

```json docs.json
"navigation": {
  "tabs": [
    {
      "tab": "Documentation",
      "groups": [
        {
          "group": "Get Started",
          "pages": ["introduction", "quickstart"]
        },
        {
          "group": "Guides",
          "pages": ["guides/authentication", "guides/webhooks"]
        }
      ]
    },
    {
      "tab": "API Reference",
      "groups": [
        {
          "group": "Endpoints",
          "pages": ["api/overview", "api/users", "api/organizations"]
        }
      ]
    }
  ]
}
```

<Note>
  Tab labels appear verbatim in the navbar, so keep them short — one or two words like "Guides", "API Reference", or "Changelog" work best.
</Note>

## Nested pages

Pages inside subdirectories are referenced using their relative path from the docs root, without the file extension. There is no special syntax — the path structure is all Mintlify needs.

```json
"pages": [
  "introduction",
  "guides/setup",
  "guides/advanced/custom-components"
]
```

Organize your files on disk the way you want them referenced in navigation. Mintlify mirrors the file structure you provide.

## Anchors

Anchors add persistent links to the bottom of your sidebar — useful for external resources like your community forum, changelog, or API status page. Define them at the top level of `docs.json`, alongside the `navigation` object.

```json docs.json
"anchors": [
  {
    "name": "Community",
    "icon": "discord",
    "url": "https://discord.gg/my-community"
  },
  {
    "name": "Changelog",
    "icon": "list",
    "url": "https://changelog.myproduct.com"
  },
  {
    "name": "Status",
    "icon": "signal",
    "url": "https://status.myproduct.com"
  }
]
```

The `icon` field accepts any icon name from the [Font Awesome](https://fontawesome.com/icons) free library. Icons render at a consistent size alongside the anchor label.

## Tips for scannable navigation

Good navigation is invisible — readers find what they need without thinking about the structure. Keep these principles in mind as you organize your docs:

- **Short group names.** Aim for one to three words: "Get Started", "Core Concepts", "API Reference". Avoid verbose labels like "Introduction and Initial Configuration Steps".
- **Short page titles.** One to three words per page title ("Authentication", "Webhooks", "Rate Limits") makes the sidebar easy to scan at a glance.
- **Logical ordering.** Lead with conceptual pages (overview, quickstart) before task-based guides, and put reference material last.
- **Limit group depth.** Mintlify supports one level of grouping within a tab. If you find yourself wanting sub-groups, it's usually a signal to split content into a separate tab instead.
- **Front-load important pages.** The first group and first page a reader sees sets the tone. Put your quickstart or "Introduction" as the very first item.
